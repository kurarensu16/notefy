## 2. Access Codes, Custom Links & Reserved Routes

- **Auto-generated codes:** Unambiguous **4-character alphanumeric** codes using `ABCDEFGHJKLMNPQRSTUVWXYZ` + `23456789` (excluding `0/O` and `1/I`), guaranteed to contain at least one letter and one digit (e.g., `K7M4`, `V8N3`).
- **Global uniqueness:** Every generated or customized edit `code` and `readOnlyCode` is checked against **both** `rooms.by_code` and `rooms.by_readOnlyCode` indexes so entering any code in `/` or the sidebar unambiguously resolves to either Edit mode or Read-Only mode.
- **Custom link rules:** Normalized lowercase (`3–40` chars, `^[a-z0-9](?:[a-z0-9-]{1,38}[a-z0-9])$`, no `--`), checked against `RESERVED_SLUGS` (`view`, `api`, `assets`, `admin`, `login`, `settings`, etc.).

## 4. Convex API Surface

### A. `convex/rooms.ts`

| Function | Type | Behavior |
| --- | --- | --- |
| `resolveCode` | Mutation | Rate-limited lookup (**15 failed attempts / 5m → 5m cooldown** per `clientId`) resolving any edit code, custom link, or read-only code (`view/` prefix stripped) to `{ kind: "edit", displayCode }`, `{ kind: "view", readOnlyCode }`, `{ kind: "not_found" }`, or `{ kind: "rate_limited", error }`. |
| `checkCodeAvailability` | Query | Live custom-link availability check (`"empty" \| "reserved" \| "invalid" \| "same" \| "taken" \| "available"`) across both edit and read-only indexes. |
| `getRoomState` | Query | Returns `"not_found"`, `"locked"` (meta only, no content), or `"ready"` (`room`, `canEdit`, `presence`). Strips `pinHash`, `pinSalt`, `expiryJobId`. |
| `getReadOnlyState` | Query | Looks up `by_readOnlyCode`. Returns `"not_found"`, `"disabled"`, `"locked"` (when `pinScope === "all"`), or `"ready"` (`room`, `presence`). |
| `getRecentMeta` | Query | Batch fetches live `title`, `displayCode`, `hasPin`, `expiresAt`, `createdAt`, `updatedAt` for up to 200 sidebar notes. |
| `createInstant` | Mutation | Allocates unique 4-char edit & read-only codes and creates a new note. |
| `createOrClaim` | Mutation | Validates a custom slug and creates a note (or returns existing room if already taken). |
| `duplicate` | Mutation | Clones `title` and `padContent` into a brand-new unique 4-char note (requires read access). |
| `updateTitle` | Mutation | Updates `title` (max 80 chars, requires edit access). |
| `updatePad` | Mutation | Updates `padContent` (max 200,000 chars) & `padUpdatedAt` (requires edit access). |
| `updateSlug` | Mutation | Updates `code` / `displayCode` with cross-index uniqueness check (requires edit access). |
| `regenerateEditCode` | Mutation | Allocates a fresh unique 4-char edit code and revokes the old edit link (requires edit access). |
| `updateReadOnly` | Mutation | Toggles `readOnlyEnabled`, sets custom `readOnlyCode`, or regenerates a fresh 4-char `readOnlyCode` (requires edit access). |
| `setRoomExpiry` | Mutation | Safely cancels prior `expiryJobId` and schedules `internal.rooms.expireRoom` for `24h` or `7d` (or clears for `never`). |
| `deleteRoom` | Mutation | Requires edit access; cancels `expiryJobId`, deletes room + sessions + presence + pinAttempts, and returns a snapshot for 5-second Undo. |
| `restoreRoom` | Mutation | Restores a deleted note snapshot (preserving its original code if still available, or allocating a fresh 4-char code). |
| `expireRoom` | Internal Mutation | Deletes expired room and all related records if `expectedExpiresAt` still matches. |

### B. `convex/security.ts` (`"use node"`)

| Function | Type | Behavior |
| --- | --- | --- |
| `setPin` | Action | Validates PIN (`4–32` chars), verifies edit access if already locked, generates 16-byte random salt + `crypto.scryptSync(pin, salt, 32)`, invalidates prior sessions, and returns a fresh 32-byte hex `sessionToken`. |
| `removePin` | Action | Verifies edit access, clears `pinHash` / `pinSalt`, and invalidates sessions. |
| `unlockRoom` | Action | Enforces rate limit (**5 failures → 5-minute cooldown** per `roomId + clientId`), compares with `crypto.timingSafeEqual`, clears failed attempts, and issues a 30-day `sessionToken`. |

### C. `convex/presence.ts` & `convex/crons.ts`
- `presence.heartbeat`: Upserts `lastSeenAt` every **25 seconds** while the tab is visible.
- `presence.leave`: Deletes the device's presence row on unmount, `pagehide`, or Leave & Clear Browser.
- Active window: **65 seconds**.
- `convex/crons.ts`: Runs `internal.presence.cleanupStale` every **15 minutes** to remove stale presence (> 5m), expired `roomSessions`, and old `pinAttempts` (> 24h).

## 5. Security, Encryption & Privacy Invariants

1. **Layer 1 — Server-Side Encryption at Rest (`convex/lib/crypto.ts`):** Every note's `title` and `padContent` is encrypted with **AES-256-GCM** (`enc:v1:<iv>:<cipher>`) using the `NOTE_ENCRYPTION_KEY` Convex environment variable before being written to the `rooms` table, and decrypted transparently on read.
2. **Layer 2 — Client-Side Zero-Knowledge E2EE (`src/lib/e2ee.ts`):** When a note is locked with *Lock entire note* (`pinScope === "all"`), the browser derives a 256-bit key locally via **PBKDF2-SHA256** (100,000 iterations, roomId-bound salt) from the user's PIN and encrypts `title` and `padContent` with **AES-256-GCM** (`e2ee:v1:<iv>:<cipher>`) before sending to Convex. The derived key is never sent to the server.
3. **Brute-Force Rate Limiting:** `resolveCode` throttles invalid access code guesses (15 failures in 5m → 5m cooldown per `clientId`), and `unlockRoom` throttles invalid PIN guesses (5 failures → 5m cooldown per `roomId + clientId`).
4. **Zero Secret Leakage:** `pinHash`, `pinSalt`, and `expiryJobId` are stripped by `toPublicRoom` / `toLockedRoomMeta` and never returned from public queries.
5. **Full Lock Enforcement (`pinScope === "all"`):** Neither `getRoomState` nor `getReadOnlyState` returns `padContent` or `title` without a valid `roomSessions` token.
6. **Edit Lock Enforcement:** Every mutating room operation verifies `requireEditAccess` against `roomSessions` when `pinHash` is set.
7. **No Orphaned Scheduled Jobs:** `safeCancelJob` cancels any existing `expiryJobId` before replacing expiry settings or deleting a room.

## 6. Client Storage & Leave & Clear Contract

| Key | Purpose |
| --- | --- |
| `notefy:clientId` | Stable browser UUID for presence & rate-limit identity |
| `notefy:recentRooms` | Up to 200 visited/created notes in this browser (`code`, `displayCode`, `title`, `visitedAt`) |
| `notefy:session:<roomId>` | Room PIN unlock session token |
| `notefy:e2ee:<roomId>` | Locally derived AES-256-GCM key for full-PIN-locked (`pinScope === "all"`) notes |
| `notefy:theme` | `"light" \| "dark"` preference |

**Leave & Clear Browser** (via `LeaveClearDialog`) either:
- **Leave only:** Calls `presence.leave`, wipes `notefy:recentRooms` and all `notefy:session:*`, rotates `notefy:clientId`, and navigates to `/` (notes remain accessible online via code).
- **Delete & leave:** Calls `rooms.deleteRoom` for the active note first, wipes local state, and navigates to `/`.
